===========================================================================

11. CREATE  CONTRIBUTING.md  (repository root)
    Reason: This is a Microsoft open-source public repo and has no CONTRIBUTING.md.
    Most senior developers check for this before engaging. It should cover:
      - How to build and test locally
      - How to run the integration test suite
      - Branch and PR conventions
      - How to add a new backend processor
      - Where to file issues vs security vulnerabilities
    Current state: BEGINNER_DEVELOPMENT.md and ADVANCED_DEVELOPMENT.md cover
    developer setup but are not linked from GitHub's standard CONTRIBUTING.md path.

12. CREATE  CHANGELOG.md  (repository root)  or link to GitHub Releases
    Reason: Public repos should surface what changed between versions.
    Currently there is no changelog visible from the repo root.
    Minimum: A link in README.md to the GitHub Releases page.

13. IMPROVE  docs/QUICKSTART.md  TL;DR section
    Current state: "Clone the repo. Deploy to Azure Container Apps or run it locally."
    This is too vague to qualify as a TL;DR. A compelling quickstart should give:
      Step 1: Clone
      Step 2: Set three required environment variables (Port, Workers, Host1)
      Step 3: docker run ... / dotnet run
      Step 4: curl http://localhost:8000/health/readiness
      Expected result: {"status":"ready","activeHosts":1}
    Readers who can run the proxy in <5 minutes become advocates. Readers who
    can't get it running in 5 minutes close the tab.
