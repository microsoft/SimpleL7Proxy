- Validate CompanionApp JSON by configuration-provider filenames: appsettings, chat-models, and vision-models, including environment variants. Other root files with a .json extension can contain newline-delimited telemetry rather than a single configuration object.
- The current WSL jq `paths(scalars)` export filter omits `false` values. Validate Boolean settings directly; do not interpret a missing exported flag as configuration-migration data loss or silently change export behavior outside scope.
- Generate deployment default-name suffixes once in DeploymentSetupPage.OnInitialized, not during rendering or export. Use the same five lowercase alphanumeric characters for new resources, without separators for ACR/storage; preserve image names, DNS zones, and existing Service Bus/Cosmos references. New setups get fresh defaults; all stages from one setup must keep the same names. Random suffixes reduce collisions but do not establish Azure name availability.
- Deployment Review uses unmodified Azure Architecture Center V24 SVGs from `https://arch-center.azureedge.net/icons/Azure_Public_Service_Icons_V24.zip` in `src/CompanionApp/wwwroot/images/azure/`, with Microsoft's bundled terms. Keep service labels beside icons and use `object-fit: contain`; do not recolor the assets or use them as the project's logo.
- Match exact current text and a unique nearby anchor when patching Razor markup. A patch with mismatched context can land inside a code method despite reporting success; an immediate focused build detects this before additional edits.
- Staged Deployment Setup exports are 01-bootstrap.json (groups/ACR), 02-publish-images.sh (explicit subscription, selected build method, image verification), and 03-application.json (existing groups/ACR). Image tags must match the publisher's `v` prefix. Do not leave ARM dependsOn entries pointing at resources created only by another stage.
- Bicep Deployment Setup exports checked-in bootstrap/main/module Bicep assets plus a generated parameters.json consumed by both deployment stages. Its deploy.sh creates the selected ACR and imports pinned releases. Because a system identity does not exist before its Container App, the application stage first creates the app with public pinned images, grants its emitted principal AcrPull, App Configuration Data Reader, and selected async roles, then updates the app to ACR images with registry identity `system`. Do not emit Host1, Port, or AZURE_CLIENT_ID as Container App environment variables; configure backends through App Configuration. Keep App Configuration value population as a separate Companion App step, resource-group deduplication case-insensitive, and the Portal and Standalone workflows independent.
- Edit the website's Bicep download templates in `src/CompanionApp/Assets/Deployment/README.template.md` and `deploy.template.sh`, not inline C# or the standalone deployment menu. CompanionApp embeds these assets; rebuild and restart it after template changes. DeploymentBicepBundle replaces `{{DEPLOYMENT_NAME}}` and `{{LOCATION}}` with complete shell-quoted values, so do not quote the tokens again. Preserve the final newline in each asset.
- Recovery instructions must use the original subscription and the script's exact deployment name; checking status does not require the bundle or restart the deployment. Existing downloaded ZIPs are not updated by source changes.
- Assign Bash command-substitution results before marking variables readonly so failed substitutions are not masked. Generated deployment-script tests must mock `az`, preserve its argument boundaries and exit codes, and cover help/input errors without contacting Azure.
- Validate Markdown emitted by C# raw strings for unindented headings and code fences, not just expected text. If an indentation-only patch preserves the wrong spacing, replace the raw-string block including its delimiters and check the generated output again.
- Integrated-browser tooling can omit native download events even when Blazor creates the correct download Blob. Check the app error state and Blob bytes, then validate the captured ZIP and compile its Bicep entry point; do not treat an event timeout alone as an application failure.
- Portal ARM exports that create resource groups must use the subscription deployment schema at the root, with root group declarations and direct `subscriptionResourceId('Microsoft.Resources/resourceGroups', ...)` dependencies from service deployments. Both resource-group-root wrapper variants produced `ResourceGroupNotFound` in user testing, including the variant containing group declarations and deployments together in an embedded subscription template. Portal scope follows the root schema. Local structure checks do not establish live Azure validation success.
- For .NET 10 file-based checks with project references, rebuild the referenced project explicitly and use `dotnet run --no-cache --file ...`; cached runs can exercise an older referenced assembly.
- Use `git --no-pager grep` as well as `git --no-pager diff`; a pager can consume later terminal commands as interactive input. This WSL Git version does not support `git grep -m`; scope the paths or filter the output instead.
- ARM resource names cannot contain runtime `reference()` calls. Pass generated values into an embedded template as parameters before using them in resource names.
- App Configuration ARM key-values with `disableLocalAuth=true` require pass-through ARM authentication and deployer data-plane permissions. Encode key/label resource names with URL encoding, then replace `~` with `~7E` and `%` with `~`.
- For editable child-component textareas in Blazor Server, use `@bind:get` / `@bind:set` with `oninput` instead of a value attribute plus an input callback; rapid typing can lose characters when parent rerenders echo older values. Test actual keyboard typing, not only Playwright fill.
- Reusing a Razor popup requires checking parent-page CSS dependencies, including help icons and hidden tooltip content. Keep ConfigurationHelp styles in the shared component so help text does not become inline content on another page.
- Native dialogs containing only fixed-position popup content need explicit dimensions. Scope browser assertions to the specific dialog class because Blazor can also render a reconnect dialog.
- Never run patches against the same files in parallel; combine edits into one patch to avoid competing contexts.
- For Deployment Setup browser checks, wait for the selected panel's controls after clicking a tab. Compare switch wrapper bounds, not the smaller checkbox bounds, when checking row alignment.
- Treat `taxonomy/concepts.json` as the canonical source for documentation concept definitions, defaults, units, reload types, status values, and protocol headers.

- **High-level understanding tone:** Follow `docs/nav/01-understand-the-proxy.md`. Begin with the reader's problem and the system's role, then explain the end-to-end flow through active, cause-and-effect language. Introduce terms in context and connect mechanisms to outcomes. Defer commands, configuration keys, defaults, and implementation caveats to task-specific documentation. Remain factual and avoid promotional claims.
- **Operator tone:** Assume technical literacy. Lead with the task, prerequisites, supported path, and expected result. Use direct, neutral instructions with exact commands, settings, defaults, units, observable signals, and recovery steps. Explain why an action matters only when that prevents an operational mistake. Do not narrate obvious commands or repeat one workflow as a summary, prose instructions, and a checklist. Organize content around setup, change, verify, and troubleshoot; avoid marketing language, self-congratulation, and unnecessary conceptual background.
